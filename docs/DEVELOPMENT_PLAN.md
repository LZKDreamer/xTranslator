# 开发计划与验收顺序

本计划由已确认的产品需求、YouTube 页面契约、工程规范与玻璃拟态设计系统组成。任何实现与评审都必须以这些文档为准。

> 时间轴修正（2026-08-25）：不同 YouTube 字幕事件保留原始 `startMs/endMs`，显示层只裁短前一条的视觉重叠，不把后一条字幕推迟到前一条结束后，避免字幕晚于音频出现。

> 译文可读性修正（2026-08-25）：中文译文保留自然标点，不再强制删除后依赖空格补偿；中文正文不人为插入词间空格，英文、数字和专有名词之间的有效空格继续保留。提示词版本升级为 `prompt-v9`，旧的无标点译文缓存自动失效。

> 划词交互修正（2026-08-25）：选区浮层增加约 280ms 防抖，连续点击或双击选区只按最终选区显示一次；设置页新增“启用划词翻译”开关，关闭后隐藏选区浮层并移除右键翻译入口，旧设置默认保持开启。

## 阶段 1：扩展基础

1. 建立 Manifest V3、TypeScript 严格模式、构建与测试命令。
2. 建立 `background`、`content`、`shared`、`popup`、`options` 包边界。
3. 建立 typed message contract、设置 schema、自动目标语言解析和 IndexedDB 基础。
4. 建立 `src/shared/icons/index.ts`，仅导出当前实际使用的图标。

验收：空扩展可加载；Popup 能显示解析后的目标语言；无 API Key 或页面权限时不报未捕获异常。

## 阶段 2：YouTube 页面适配与字幕

1. 按 `YOUTUBE_PAGE_CONTRACT.md` 解析 `ytInitialPlayerResponse` 并校验视频/字幕字段。
2. 实现播放器触发器、标题/简介状态提示容器与 YouTube SPA 页面切换后的幂等重新挂载。
3. 实现字幕请求、运行时解析校验、稳定分段 ID 和字幕显示模式。
4. 为字幕读取失败、临时 URL 失效、字段缺失建立可恢复错误状态；有效视频无字幕时保持安静。

> 已验证实现（2026-08-24）：字幕读取采用 **MAIN world bridge**（`content/main-world-bridge.ts`）捕获播放器自身的 timedtext 响应——timedtext 要求 `pot`（无 `pot` 返回空 200），且“挂载时 baseUrl + 单独 pot”的二次请求不可靠，故以播放器实际请求正文为准。`fmt=json3` 的 pb3 事件格式已在真实数据上验证；触发选轨时用注入样式临时隐藏字幕层以避免原生字幕闪现，读取完成后恢复字幕状态。解析器跳过无 `segs` 的事件并接受数字/字符串时间。

验收：对已验证视频可显示真实字幕轨道；切换视频不会重复注入；缓存不包含临时 `baseUrl`。

> 已实现（2026-08-25）：YouTube 缺少 `captions` 或字幕轨道时仍识别为有效视频，不显示“当前 YouTube 页面暂不支持读取”或播放器翻译按钮；只有无法识别观看页时才显示页面级提示。设置页字幕模式通过 `chrome.storage.local` 变更事件同步到当前字幕叠加层，切换原文、译文或双语后无需重新翻译即可立即生效。

## 阶段 3：LLM 与缓存

1. 建立统一 Provider adapter、结构化输出校验、分块和重试策略。
2. 实现至少一个 OpenAI-compatible preset 和一个 Anthropic Messages adapter，先实现DeepSeek；其余 provider 通过 registry 扩展。
3. 完成视频字幕缓存、缓存清理、缓存版本与语言维度。

> 已实现（阶段 3，自动化验证）：provider 通过版本化 registry 注册，翻译管线支持 token 估算、块级翻译、句末预拆分、500ms 自然停顿、6 秒时长上限、稳定 block ID 回填、字幕标记清理和自然标点保留；解析器合并重复事件并保持不同事件的原始时间，显示层裁短视觉重叠以避免字幕晚于音频。字幕译文按批次缓存到 IndexedDB，长视频超时后可继续补译；设置页提供字幕模式、翻译记录和划词翻译开关。当前自动化验证为类型检查、140 项测试与构建；真实 YouTube + 真实 API Key 的全链路 smoke test 仍需人工确认。
> 更新（2026-08-25）：长视频翻译改为按批次增量保存进度；超时或部分失败时返回并显示已完成 block，播放器按钮提示“重试未完成翻译”，再次点击只补译缺失 block。当前自动化验证为 `pnpm typecheck`、140 项测试与 `pnpm build`；真实 YouTube + 真实 API Key 的长视频续译仍需人工 smoke test。

> 已实现（2026-08-25，长视频失败恢复）：每个完成的翻译批次立即写入 IndexedDB；超时或部分失败时返回并显示已完成块，播放器按钮提示“重试未完成翻译”，后续点击只补译缓存缺失 block。新增回归测试覆盖“前一批成功、后一批超时”的增量保存与续译响应。

> 字幕处理对照记录（2026-08-25）：参考项目采用词级时间戳，按句末标点、约 500ms 停顿、6 秒/字符上限切分，并在后处理阶段清理重复和重叠字幕。本插件当前拿到的是 YouTube JSON3 的事件级/片段级时间，因此采用可验证的适配方案：句末预拆分、500ms 停顿、6 秒块上限、重叠归一化和目标语言清洗；不直接按固定字符数硬切，避免没有词级时间锚点时把完整句子拆成两段。

验收：短视频和分块长视频均能按时间轴回填译文；再次打开同视频可命中缓存；长视频批次失败后已完成字幕仍可显示，重试只补译缺失 block；日志无 Key 和正文。

## 阶段 4：评论与划词

1. 通过 DOM 观察处理真实渲染的评论线程、展开回复和懒加载。
2. 实现翻译可见评论、单条和线程级翻译，不直接调用 YouTube 内部 continuation API，翻译的文本显示在原文下方。
3. 实现划词浮层与右键菜单。

> 阶段 4 行为补充（2026-08-25）：评论批量入口对外文案为“翻译可见评论”；划词浮层使用约 280ms 选区防抖，设置页的 `settings.selection.enabled` 控制页面浮层和右键菜单，关闭后不再创建右键翻译入口。当前自动化验证为 140 项测试。

> 已实现（阶段 4，自动化验证）：评论翻译观察 YouTube 已渲染的评论 DOM，只提供“翻译可见评论”、单条和“翻译这组评论”入口，不调用 continuation API；批量入口会随滚动和懒加载重新锚定，范围只包含当前可见评论。划词翻译提供选区浮层和右键菜单，浮层增加约 280ms 防抖以等待最终选区；设置页的 `settings.selection.enabled` 控制页面浮层和右键菜单，默认开启，关闭后立即移除浮层和右键入口；`settings.selection.includeContext` 独立控制是否附带前后句上下文。当前自动化验证为类型检查、140 项测试与构建；真实 YouTube 页面仍需人工确认评论懒加载、选区双击和开关切换。

验收：评论折叠/展开和滚动加载不产生重复请求；选区翻译不改写原页面文本。

## 阶段 5：视觉与质量

1. 按 `DESIGN_SYSTEM.md` 应用 macOS 玻璃拟态，并从已选 Logo 方向制作所需尺寸品牌资产。
2. 验证深/浅色表面、键盘访问、减少动效与多语言文本溢出。
3. 运行类型检查、单元测试、fixture 测试和人工 YouTube smoke test。

> 已实现（2026-08-25）：播放器翻译、“翻译可见评论”和“翻译这组评论”三个主入口统一使用已选 Logo 方向的品牌标记；播放器使用深色版本，评论区浅色表面使用浅色版本。入口仍保留可见文字与本地化 aria-label，加载/完成/失败状态继续使用功能状态图标。品牌资源加载器独立于内联功能图标出口。

> 已实现（2026-08-25）：字幕层已改为按实际视频 viewport 定位，双语字幕使用一个紧凑卡片，译文在上且字号约 16–19px，原文在下且字号约 13–15px；卡片约 62% 黑色透明背景、宽度不超过视频区域约 92%，单行优先并使用自然换行。字幕模式切换会立即应用到当前视频。字幕处理同时补充句末预拆分、500ms 停顿、6 秒块时长上限、重复事件合并和显示层重叠裁剪、中文译文保留自然标点和标点-only 字幕过滤。Popup 与设置页统一为浅色 macOS 玻璃拟态，使用冷色光晕背景、半透明面板、24px 背景模糊、细高光描边、次级玻璃控件和深色玻璃 Toast；设置页补充下拉框键盘焦点和减少动效处理。Popup 配置卡片统一卡片间距并更新为产品化文案，设置页字段改为变更后自动保存并移除手动保存按钮。针对“完整译文提前显示在前一段、后一段只剩原文”的问题，block 源 token 上限保持约 48，并增加连续句、咖啡冲煮、清洗、重叠时间和长时长字幕回归测试。

验收：视觉、交互、数据和隐私要求均通过；未验证的页面结构不会被当作可靠接口使用。当前自动化验证为 `pnpm typecheck`、140 项测试与 `pnpm build`；Popup/设置页已完成本地渲染检查，仍需在目标 YouTube 页面完成最终人工 smoke test。
