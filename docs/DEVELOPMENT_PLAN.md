# 开发计划与验收顺序

本计划由已确认的产品需求、YouTube 页面契约、工程规范与玻璃拟态设计系统组成。任何实现与评审都必须以这些文档为准。

> 时间轴修正（2026-08-25）：不同 YouTube 字幕事件保留原始 `startMs/endMs`，显示层只裁短前一条的视觉重叠，不把后一条字幕推迟到前一条结束后，避免字幕晚于音频出现。

> 译文可读性修正（2026-08-25）：中文译文保留自然标点，不再强制删除后依赖空格补偿；中文正文不人为插入词间空格，英文、数字和专有名词之间的有效空格继续保留。当前提示词版本为 `prompt-v10`；缓存数据库 schema 已升级为 v4，旧结构记录在升级时清理。

> 划词交互修正（2026-08-25）：选区浮层增加约 100ms 防抖，连续点击或双击选区只按最终选区显示一次；设置页新增“启用划词翻译”开关，关闭后隐藏选区浮层并移除右键翻译入口，旧设置默认保持开启。

## 阶段 1：扩展基础

1. 建立 Manifest V3、TypeScript 严格模式、构建与测试命令。
2. 建立 `background`、`content`、`shared`、`popup`、`options` 包边界。
3. 建立 typed message contract、设置 schema、自动目标语言解析和 IndexedDB 基础。
4. 建立 `src/shared/icons/index.ts`，仅导出当前实际使用的图标。

验收：空扩展可加载；Popup 能显示解析后的目标语言；无 API Key 或页面权限时不报未捕获异常。

## 阶段 2：YouTube 页面适配与字幕

1. 按 `YOUTUBE_PAGE_CONTRACT.md` 解析 `ytInitialPlayerResponse` 并校验视频/字幕字段。
2. 实现播放器触发器、标题/简介状态提示容器与 YouTube SPA 页面切换后的幂等重新挂载。
3. 实现字幕请求、运行时解析校验、稳定分段 ID 和字幕显示模式。
4. 为字幕读取失败、临时 URL 失效、字段缺失建立可恢复错误状态；有效视频无字幕时保持安静。

> 已验证实现（2026-08-24）：字幕读取采用 **MAIN world bridge**（`content/main-world-bridge.ts`）捕获播放器自身的 timedtext 响应——timedtext 要求 `pot`（无 `pot` 返回空 200），且“挂载时 baseUrl + 单独 pot”的二次请求不可靠，故以播放器实际请求正文为准。`fmt=json3` 的 pb3 事件格式已在真实数据上验证；触发选轨时用注入样式临时隐藏字幕层以避免原生字幕闪现，读取完成后恢复字幕状态。解析器跳过无 `segs` 的事件并接受数字/字符串时间。

> 轨道绑定补充（2026-08-26）：默认选择首个非 `asr` 轨道，否则选择首个可用轨道；当前实现尚未提供手动源字幕轨道选择 UI。MAIN world bridge 只在存在匹配的当前视频/轨道请求时接收字幕正文，并校验 URL 中出现的 `vss_id`、`lang`、`kind`，避免并发加载或旧请求串入当前翻译。

验收：对已验证视频可显示真实字幕轨道；切换视频不会重复注入；缓存不包含临时 `baseUrl`。

> 已实现（2026-08-25）：YouTube 缺少 `captions` 或字幕轨道时仍识别为有效视频；只要当前视频存在字幕轨道，无论原生字幕按钮开启、关闭还是不可用，都显示播放器翻译按钮。仅当字幕轨道为空且字幕按钮不满足明确的 DOM 条件时才隐藏：按钮不能含 `aria-disabled="true"`、`disabled` 属性或 `ytp-button-disabled` class，并且必须含 `aria-pressed="true"` 或 `ytp-button-pressed` class。按钮首次显示前等待约 200ms 复核播放器状态，同一视频的临时不完整响应不会移除已显示按钮。YouTube 的全局“默认开启字幕”偏好不单独触发按钮显示。只有无法识别观看页时才显示页面级提示。设置页字幕模式通过 `chrome.storage.local` 变更事件同步到当前字幕叠加层，切换原文、译文或双语后无需重新翻译即可立即生效。

## 阶段 3：LLM 与缓存

1. 建立统一 Provider adapter、结构化输出校验、分块和重试策略。
2. 实现至少一个 OpenAI-compatible preset 和一个 Anthropic Messages adapter，先实现DeepSeek；其余 provider 通过 registry 扩展。
3. 完成视频字幕缓存、缓存清理、缓存版本与语言维度。

> 已实现（阶段 3，自动化验证）：provider 通过版本化 registry 注册，翻译管线支持 token 估算、块级翻译、句末预拆分、500ms 自然停顿、16 秒硬时长上限、稳定 block ID 回填、字幕标记清理和自然标点保留。相同开始时间保持 JSON3 原始顺序；重叠重复事件归一化但保留不同事件的时间，重叠的标记事件不强制切块；无标记内容的块不送入 LLM，短的无标点续句会在满足时间、token 和总时长条件时合并。字符上限只作为可读性保护，不单独把完整原始事件按字符数截断。显示层仍只裁短视觉重叠，避免字幕晚于音频。

> 长视频失败恢复（2026-08-26）：每个完成的翻译批次立即写入 IndexedDB，并保存完整定时 block（源文、译文、时间范围、segment IDs）；超时或部分失败时返回并显示已完成块，播放器按钮提示“重试未完成翻译”，后续点击只补译缓存缺失 block。缓存读取和增量续译必须同时匹配视频 ID、源轨道指纹、源语言和目标语言；数据库 schema v4 清理不兼容旧记录。当前自动化验证为 `pnpm check`：类型检查、27 个测试文件共 164 项测试与构建；真实 YouTube + 真实 API Key 的全链路 smoke test 仍需人工确认。

> 设置页翻译服务配置（2026-08-26）：服务商、API Key 和模型改为草稿与已保存配置分离，三项完整后原子保存；模型列表除 Agnes AI 外从服务商的 `/models` 接口运行时获取；不同服务商分别记忆 API Key 和模型，未完成配置不触发全局错误提示。字幕、划词和缓存设置继续分区保存。

验收：短视频和分块长视频均能按时间轴回填译文；再次打开同视频可命中缓存；长视频批次失败后已完成字幕仍可显示，重试只补译缺失 block；日志无 Key 和正文。

## 阶段 4：评论与划词

1. 通过 DOM 观察处理真实渲染的评论线程、展开回复和懒加载。
2. 实现翻译可见评论、单条和线程级翻译，不直接调用 YouTube 内部 continuation API，翻译的文本显示在原文下方。
3. 实现划词浮层与右键菜单。

> 阶段 4 行为补充（2026-08-25）：评论批量入口对外文案为“翻译可见评论”；划词浮层使用约 100ms 选区防抖，设置页的 `settings.selection.enabled` 控制页面浮层和右键菜单，关闭后不再创建右键翻译入口。当前自动化验证为 164 项测试。

> 已实现（阶段 4，自动化验证）：评论翻译观察 YouTube 已渲染的评论 DOM，只提供“翻译可见评论”、单条和“翻译这组评论”入口，不调用 continuation API；批量入口会随滚动和懒加载重新锚定，范围只包含当前可见评论。划词翻译提供选区浮层和右键菜单，浮层增加约 100ms 防抖以等待最终选区；设置页的 `settings.selection.enabled` 控制页面浮层和右键菜单，默认开启，关闭后立即移除浮层和右键入口；`settings.selection.includeContext` 独立控制是否附带前后句上下文。当前自动化验证为类型检查、164 项测试与构建；真实 YouTube 页面仍需人工确认评论懒加载、选区双击和开关切换。

验收：评论折叠/展开和滚动加载不产生重复请求；选区翻译不改写原页面文本。

## 阶段 5：视觉与质量

1. 按 `DESIGN_SYSTEM.md` 应用 macOS 玻璃拟态，并从已选 Logo 方向制作所需尺寸品牌资产。
2. 验证深/浅色表面、键盘访问、减少动效与多语言文本溢出。
3. 运行类型检查、单元测试、fixture 测试和人工 YouTube smoke test。

> 已实现（2026-08-25）：播放器翻译、“翻译可见评论”和“翻译这组评论”三个主入口统一使用已选 Logo 方向的品牌标记；播放器使用深色版本，评论区浅色表面使用浅色版本。入口仍保留可见文字与本地化 aria-label，加载/完成/失败状态继续使用功能状态图标。品牌资源加载器独立于内联功能图标出口。

> 已实现（2026-08-25）：字幕层已改为按实际视频 viewport 定位，双语字幕使用一个紧凑卡片，译文在上且字号约 16–19px，原文在下且字号约 13–15px；卡片约 62% 黑色透明背景、宽度不超过视频区域约 92%，单行优先并使用自然换行。字幕模式切换会立即应用到当前视频。字幕处理同时补充句末预拆分、500ms 停顿、16 秒块时长上限、重复事件合并和显示层重叠裁剪、中文译文保留自然标点和标点-only 字幕过滤；短的无标点续句会在安全条件下合并。Popup 与设置页统一为浅色 macOS 玻璃拟态，使用冷色光晕背景、半透明面板、24px 背景模糊、细高光描边、次级玻璃控件和深色玻璃 Toast；设置页补充下拉框键盘焦点和减少动效处理。Popup 配置卡片统一卡片间距并更新为产品化文案，翻译服务设置改为三项完整后原子保存、按服务商恢复配置，字幕与划词设置独立自动保存并移除手动保存按钮。针对“完整译文提前显示在前一段、后一段只剩原文”的问题，block 源 token 上限保持约 48，并增加连续句、咖啡冲煮、清洗、重叠时间和长时长字幕回归测试。

验收：视觉、交互、数据和隐私要求均通过；未验证的页面结构不会被当作可靠接口使用。当前自动化验证为 `pnpm check`（类型检查、164 项测试与构建）；选项页已完成构建产物的静态 DOM/CSS 检查，浏览器本地文件自动化受 URL 安全策略限制，仍需在目标 YouTube 页面完成最终人工 smoke test。
