# 产品需求基线

## 产品定位

xTranslator 是一个 BYOK（用户自带翻译服务密钥）的 Chrome Manifest V3 扩展。它在 YouTube 观看页上提供语境翻译，不篡改 YouTube 源内容：观看页字幕由自绘叠加层在视觉上“取代”原生字幕，但原始字幕与数据始终保留，可随时切回。

> 字幕译文可读性约定（2026-08-25）：译文保留自然标点，用于表达停顿、疑问和语气；中文正文不人为插入词间空格，英文、数字和专有名词之间的有效空格保留。仅清理字幕标记和装饰性噪声。

## 语言解析

目标语言**不提供手动设置**，始终按浏览器界面语言自动解析，并在本次任务中固定：

1. `chrome.i18n.getUILanguage()`；
2. `navigator.languages[0]`；
3. `navigator.language`；
4. `en`。

解析结果必须规范化为 BCP-47 标签。中文需要保留文字体系：`zh-CN` 映射为 `zh-Hans`，`zh-TW` 映射为 `zh-Hant`。缓存键保存解析后的实际目标语言标签，而不是 `auto`。Popup 顶部显示“翻译语言”，详情为“自动跟随浏览器语言 · <语言名称>”，不直接展示 BCP-47 标签。

## 视频翻译

- 读取视频 ID、标题、简介、时长与可用字幕轨道。
- 让用户选择源字幕轨道；默认优先非自动字幕，其次默认音轨对应的自动字幕。
- 字幕只使用 MAIN world bridge 捕获的 YouTube 播放器真实 `fmt=json3` 响应；不读取 `.srt`/`.txt`，也不直接请求临时 `baseUrl`。
- 将 JSON3 解析为保留 `tStartMs`、`dDurationMs` 和 fragment offset 的时间片段；先按句末标点拆开同一事件中的多句，再按**自然停顿（时间缺口）、6 秒时长上限与 token 预算**合并成“翻译块”。合并不能跨完整句，未完句优先保持在同一时间 block，只有超过硬上限才在语义边界切分；解析阶段合并重叠重复事件，不改写不同事件的原始时间，显示层仅裁短前一条的视觉重叠，避免后一条字幕晚于音频出现；最终显示可在背景框内换行，但不得截断。
- LLM 负责：**把碎片合并成通顺的字幕行**、**去掉 `[music]`/`[applause]`/音符等无意义标签**、修正明显 ASR 断句与同音误识；所有目标语言保留自然标点，清理字幕标记和装饰性噪声；中文正文不人为插入词间空格，英文、数字和专有名词之间的有效空格保留；自然口语化，保留说话人语气，避免书面腔；不得借用相邻 block、虚构内容或改变事实。无语音的块不调用 LLM、不显示字幕。
- 译文按**稳定 block ID 回填到同一时间范围**，不按模型返回顺序匹配，时间戳由程序控制；翻译完成后在观看页字幕位置以字幕叠加层显示（激活时持续隐藏原生字幕窗口以在视觉上“取代”它），不在标题/简介区域额外渲染译文面板。有效视频没有字幕时不显示页面级错误提示或翻译按钮。
- 字幕提供**原文、译文、双语**三种模式（设置页选择，默认双语）；双语为**译文在上（黄色）、原文在下**。字幕层以视频实际显示区域为基准，使用一个紧凑背景卡片，译文为主层级、原文为辅助层级，单行优先、过长自动换行，不能超出屏幕或背景框。模式保存后，正在播放的视频字幕层立即重绘。
- 非静音 block 的空译文视为失败：会重试、不会写入有效缓存；旧缓存中的空译文会重新翻译。多次仍缺失时显示可恢复错误，不伪装成翻译成功。
- 支持短视频与分块长视频；长视频按块分批请求，并尽量命中缓存。每个已完成批次立即写入缓存；超时或部分失败时继续显示已完成块，播放器按钮明确提示“重试未完成翻译”，再次点击只请求缺失 block。
- Provider preset 可声明模型级最大输出 token；字幕请求不得超过该上限，不能把大上下文窗口直接当作输出上限。

## 评论翻译

- 主入口（翻译可见评论）只翻译当前已由 YouTube 渲染并显示的评论，绝不因翻译而展开折叠回复。按钮随滚动和 YouTube 懒加载重新锚定到当前视口内第一个完整可见的顶级评论；后续评论进入视口后仍可从该入口翻译。若翻译失败，按钮显示“重试”；点按会重试当前可见评论中失败或尚未翻译的部分。
- 当父评论的回复已展开时，显示完整可点击的“翻译这组评论”按钮（图标和文字都可点），将父评论及当前已展开的全部回复送入同一请求。展开/收起回复始终由 YouTube 自己的控件负责。
- 不主动请求或伪造 YouTube 内部 continuation 接口来提前获取下一页、折叠回复或隐藏评论（仅点按页面自己的“查看 N 条回复 / 查看回复”控件，展开后按“已渲染”处理）。
- 使用 token 上限批处理；滚动导致的新评论仅在进入可见区或用户主动翻译时入队。
- 评论上的重复“翻译”入口已精简：仅保留“翻译可见评论”（评论区头部）与已展开回复的父评论上的“翻译这组评论”，避免与 YouTube 自身的回复展开控件混淆。

## 划词翻译

- 划词翻译默认开启，可在设置页关闭；启用时选中网页文本后显示轻量浮动操作，同时提供右键菜单入口。
- 连续点击、双击或拖动选区时，浮层等待约 280ms 后只按最终选区显示，不能先为中间选中的单词弹出翻译浮层。
- 默认只发送选区；可选“附带前后一句上下文”。
- 结果可复制和关闭，不能改变被选中的原始文本节点。

## 缓存与隐私

- 缓存存入 IndexedDB，包含解析后的文本、译文与视频标题；不包含短期有效的字幕 URL、LLM Key 或完整请求日志。
- 视频缓存键：`videoId + sourceTrackFingerprint + sourceLanguage + targetLanguage + promptVersion`（值为解析后的目标语言标签）。
- 缓存以“翻译块 ID → 译文”存储；已完成批次会增量写入，`promptVersion` 或目标语言变化即失效；空译文不作为有效缓存命中。
- 支持按视频（标题列出）删除、全部删除与占用空间展示；缓存列表以“标题 + `源→目标 · 块数 · 时间`”两行排版。
- API Key 只存于扩展本地存储；不得使用 `chrome.storage.sync`、DOM 属性、页面脚本变量或控制台日志。
- 设置页的翻译服务、服务密钥、翻译模型、字幕模式、划词翻译开关和划词上下文选项均在变更后自动保存；服务密钥输入采用短暂防抖，页面不提供“保存更改”按钮。

## LLM 接入

供应商配置分为 OpenAI-compatible、Anthropic Messages 与 Provider preset。Provider 的 Base URL、模型列表和能力必须来自版本化配置或运行时模型发现，不能散落在 UI 或业务代码里。

- 模型列表通过各 provider 的 `GET /models`（OpenAI-compatible 为 `/models` 或 `/v1/models`，Anthropic 为 `/v1/models`）**运行时拉取**，设置页据此生成模型下拉并默认选中其一；无 API Key 或拉取失败时如实提示，**不编造模型列表**。
- 对多协议网关（如 OpenCode Zen：GPT/Grok/Muse 走 `/responses`，Claude/Qwen 走 `/messages`，Gemini 走 `/models/{id}`，仅 DeepSeek/MiniMax/GLM/Kimi 等走 OpenAI 兼容 `/chat/completions`）：模型下拉只暴露当前适配器真正支持的那批模型（按 preset 的 `modelAllowlist` 过滤 `/models` 结果），避免用户选到不兼容协议而报错。
- 所有请求必须经过统一适配器，返回统一的结构化翻译结果（块级 `{id, text}`）。源文本被视为不可信输入；系统提示词必须要求模型忽略源文本中的任何指令，并合并碎片、去除非语言标签。
- 失败原因映射为面向用户的中文提示（Key 无效 / 限流 / 超时 / 网络 / 模型不可用 / 服务商异常），日志不含 Key 与请求/响应正文。
